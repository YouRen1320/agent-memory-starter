# Adoption Checklist

## 中文

1. 先确认你支持哪些工具，不要为了“看起来统一”而加一堆没人用的桥接文件。
2. 决定 `AGENTS.md` 里只放“共享真源”，不要把所有日志和细节都堆进去。
3. 决定 `MEMORY.md` 里记录哪些长期有效的信息，避免把短期临时内容写进去。
4. 决定 `memory/` 是否提交到 Git，还是只在本地保留。
5. 如果要做全局层，确认全局路径是可靠的；不确定就标注“不确认”。
6. 开源前选择许可证，并明确哪些内容是示例、哪些内容是你的真实偏好。

## English

1. Confirm which tools you actually support instead of adding bridges just for appearance.
2. Keep `AGENTS.md` focused on the shared source of truth rather than dumping every log into it.
3. Decide what durable information belongs in `MEMORY.md` so temporary notes do not accumulate there.
4. Decide whether `memory/` should be committed to Git or kept local only.
5. If you add global setup docs, confirm the paths are real; if uncertain, label them as uncertain.
6. Choose a license before publishing and make it clear which content is example text versus real policy.
